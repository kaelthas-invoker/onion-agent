# EP54：Agent 的内核就是一个 while 循环

```bash
git checkout ep54
```

## 问题

让 Agent 写一个 `fizzbuzz.py`，打印 1 到 15，再运行它。模型回得很快：文件名、整段代码、运行命令都给了，可 `workspace` 里什么都没有。终端里它跑了 20 轮，每一轮标题都是「发给模型 1 条消息」，每一轮都在要工具（20 轮里要了 14 次写文件、14 次 bash），最后是被轮数上限停下来的。

原因在于模型自己什么都做不了。function calling 只让模型能在回复里说「我想调用 `write_file`，参数是这些」；真正去执行的，必须是模型外面的程序。执行完还得把结果交回去，模型才知道刚才发生了什么、下一步该做什么。上面那次，循环里执行和交回结果的四行被注释掉了。

## 解决方案

在模型外面写一个 while 循环：

1. 把到目前为止的全部消息发给模型；
2. 回复里没有工具调用，说明模型认为做完了，返回它的回答；
3. 有工具调用，先把这条回复原样记进消息，再逐个执行；
4. 每个结果作为一条工具消息追加回去，回到第 1 步。

这就是 Agent 的内核。[`onion_agent/loop.py`](../onion_agent/loop.py) 一共 60 行，去掉注释和空行 28 行；上面那次缺的，就是第 43、47、48、50 这四行。

这一期只做循环本身和三个最基本的工具：`read_file`、`write_file`、`bash`。流式输出、上下文压缩、会话保存、重试、多轮对话都不做，它们是后面各期的层。

## 跟练：从注释掉四行开始，两步接上

打开 [`onion_agent/loop.py`](../onion_agent/loop.py)，把下面四行在行首加 `#` 注释掉，这就是起点：

| 行 | 代码 | 作用 |
| --- | --- | --- |
| 43 | `messages.append(reply)` | 把模型这条回复原样记进消息 |
| 47 | `result = call_tool(tools_by_name, name, arguments)` | 执行工具 |
| 48 | `on_event("tool_result", call.id, result)` | 在终端显示结果 |
| 50 | `messages.append({"role": "tool", "tool_call_id": call.id, "content": result})` | 把结果写回消息，带上调用编号 |

每一步都跑同一个任务，跑之前先 `rm -rf workspace`：

```bash
uv run --env-file .env onion-agent "在 workspace 里写一个 fizzbuzz.py，打印 1 到 15 的结果，然后运行它确认输出正确"
```

| 步骤 | 放开哪几行 | 你应该看到 | 检查点 |
| --- | --- | --- | --- |
| 起点 | 无 | 模型每轮都在要工具，但什么都没执行；跑满 20 轮后停下，最后一行是「[已停止] 跑满了轮数上限」 | 每轮标题都是「1 条消息」；`ls workspace` 是空的 |
| 第一步：执行 | 47 | 工具真的执行了，模型却一遍遍重新要写文件，同样跑满 20 轮才停 | `workspace` 里有了 `fizzbuzz.py`；标题还是「1 条消息」 |
| 第二步：写回 | 43、48、50 | 每个工具调用下面多一行绿色的「◀ 结果追加回去」，编号和上面那行对得上；模型写完文件去运行，然后回答，循环自己结束 | 消息数 1 → 3 → 5…；`python3 workspace/fizzbuzz.py` 的第 3、5、15 行是 Fizz、Buzz、FizzBuzz |

起点和第一步都要跑满 20 轮，大约半分钟到一分钟，不想等可以 `Ctrl+C`。第一步开始会执行 bash，每条命令都会问 `y/N`，可以加 `--yes` 跳过（只在这个练习目录里这么做）。

**第一步为什么写了 20 遍还不知道？** 结果没交回去：每一轮发给模型的，还是最开始那一条任务，它看不到自己刚才做了什么，只能从头再来。

**最容易漏的是第 43 行。** 只放开 48、50，不放开 43，接口不会报错，模型也照样往下走，最后也给出答案（百炼 `deepseek-v4.1-flash` 上实测，5 轮后照样回答，全程没报错）。唯一的信号是消息数：每一轮多出来的消息，应该等于这一轮的工具调用数再加 1（多的那一条是模型自己的回复）。比如第 1 轮调了两个工具，第 2 轮应该是 4 条；漏了第 43 行就只有 3 条，只多出了调用数。

模型每次的走法不一样，你跑出来的轮数不一定是 3。开发时同一个任务跑出过 5 轮：第 3 轮模型想用 `<(...)` 逐行比对输出，可工具叫 `bash`、实际执行的是 `/bin/sh`，退出码 2；第 4 轮它自己换成临时文件比对，临时文件写到了 `/tmp`，在工作目录外面，因为这一版没有沙箱。要对照的是「消息数涨没涨」「目录里有没有文件」「模型下一步做了什么」这三件事。

## 工作原理

先看 [`loop.py`](../onion_agent/loop.py) 里的 `run()`，循环的每一步都在这里：

| 步骤 | 做什么 | 代码 |
| --- | --- | --- |
| 准备 | 消息历史里只有一条用户任务；每个工具转成模型认识的 JSON Schema | `messages = [...]`、`tool.schema()` |
| 0. 保险 | 最多跑 `MAX_TURNS = 20` 轮 | `while turn < MAX_TURNS:` |
| 1. 问模型 | 把全部消息和工具列表发给模型 | 第 35 行 `client.chat.completions.create(...)` |
| 2. 判断结束 | 回复里没有 `tool_calls`，说明模型认为做完了，返回它的文本 | 第 39–40 行 `if not reply.tool_calls: return ...` |
| 3. 执行工具 | 先把模型这条回复原样记进历史，再按顺序执行每个工具调用 | 第 43 行 `messages.append(reply)`、第 44–47 行 |
| 4. 交回结果 | 每个结果作为一条 `role=tool` 的消息追加回去，带上 `tool_call_id`，然后进入下一轮 | 第 50 行 `messages.append({"role": "tool", ...})` |

拿 [examples/ep54-multi-call.txt](../examples/ep54-multi-call.txt) 的第 1 轮来说，这一轮结束时 `messages` 长这样（id 做了简化）：

```text
[
  {"role": "user", "content": "只用 write_file 和 read_file：同时新建 a.txt 和 b.txt ..."},
  {"role": "assistant", "tool_calls": [
      {"id": "call_1", "function": {"name": "write_file", "arguments": "{\"path\": \"a.txt\", \"content\": \"A\"}"}},
      {"id": "call_2", "function": {"name": "write_file", "arguments": "{\"path\": \"b.txt\", \"content\": \"B\"}"}}]},
  {"role": "tool", "tool_call_id": "call_1", "content": "已写入 a.txt（1 字符）"},
  {"role": "tool", "tool_call_id": "call_2", "content": "已写入 b.txt（1 字符）"},
]
```

第 2 轮模型看到的就是这四条，所以它知道自己刚才做了什么、结果如何。终端里第 2 轮的标题也写着「发给模型 4 条消息」。

终端输出和循环的步骤一一对应（在真终端里带颜色，重定向到文件时不带）：

| 终端里看到的 | 对应 `run()` 里的 |
| --- | --- |
| 青色 `━━ 第 N 轮 · 发给模型 M 条消息 ━━` | 步骤 1，M 就是 `len(messages)` |
| 黄色 `▶ 模型要调用 工具名  call_…` | 步骤 3：第 46 行，后面是这次调用的编号 |
| 绿色 `◀ 结果追加回去  call_…`（工具抛了异常或被拒绝时是红色；bash 命令退出码不是 0 不算异常，仍是绿色） | 步骤 4：第 48 行打印、第 50 行追加，编号和上面那行对得上 |
| 绿色 `━━ 最终回答 ━━` | 步骤 2；跑满 `MAX_TURNS` 时也打这个标题，下面是「[已停止] 跑满了轮数上限……」 |

几个值得停下来看的细节：

- **为什么 `messages.append(reply)` 原样追加？** 模型的回复里带着 `tool_calls` 和每个调用的 `id`，后面的 `role=tool` 消息要靠 `tool_call_id` 对上号。原样追加也会把服务商返回的额外字段一起带回去，比如推理模型的 `reasoning_content`。百炼上的 `deepseek-v4.1-flash` 实测接受这样回传；各家对这类字段的要求不一样，换服务后如果报 400，先看这一行。
- **为什么工具出错不抛异常？** [`call_tool()`](../onion_agent/loop.py)（第 55–60 行）把任何异常（文件不存在、参数缺失、JSON 坏了、工具名不存在、命令超时）都变成一段文字交还给模型。模型看到「FileNotFoundError」会自己换个办法，循环不会因为一个工具挂掉就崩。
- **为什么只有一道保险？** 模型可能一直调工具停不下来，`MAX_TURNS` 保证循环一定会结束，跑满时返回的文字会说明是因为超了上限才停的。「什么时候该停」本身是一个设计问题，EP55 展开讲。
- **循环本身不打印任何东西。** 它通过 `on_event` 把每一步告诉调用方，终端里怎么显示由 [`cli.py`](../onion_agent/cli.py) 的 `show()` 决定。

然后是 [`tools.py`](../onion_agent/tools.py)。每个工具就是一个 `Tool`：名字 + 描述 + 参数的 JSON Schema + 一个 Python 函数。`make_tools(workdir, confirm)` 造出绑定到工作目录的三个工具：

- `read_file(path)`、`write_file(path, content)`：路径相对工作目录（默认 `./workspace`）。工作目录写进了工具描述，不然模型听到「在 workspace 里」会再套一层 `workspace/`。
- `bash(command)`：在工作目录里执行命令，超时 30 秒，输出超过 10000 字符就截断并注明。执行前在终端完整打印命令、问你 `y/N`；你拒绝时，模型收到的结果是「用户拒绝执行这条命令。」这是最原始的审批，沙箱在 EP58 讲，审批分层在 EP59 讲。

### 这一版故意没做的

这一版故意保持最简单，下面这些坑是知道的，交给后面的层：

- 运行中按 `Ctrl+C`，Python 直接抛 `KeyboardInterrupt`，终端刷出一大段 traceback（第 2 轮按停那次是 86 行），写出的文件留着，这一次的消息历史全丢了。怎么好好停下来在 EP55 讲。
- 跑满 `MAX_TURNS` 那一轮的工具照样会执行（bash 照样问你），只是结果模型已经看不到了。停止条件也在 EP55。
- `bash` 的输出先整段读进内存再截断。模型写出死循环狂打印的脚本时，30 秒超时之前内存能涨到几个 GB；`yes` 这类全速输出的命令最坏能把内存吃光。资源限制属于沙箱（EP58）。
- 超时只杀掉 shell 本身，它启动的子进程可能留下来；命令里用 `&` 起后台进程（比如开一个 dev server）时，会一直等满 30 秒再报超时。
- `read_file` 一次读出整个文件，不截断，大文件会把下一次请求撑到超长报错；`write_file` 只能整个覆盖写，没有追加，也不能只改一处。怎么改文件在 EP57 讲，上下文管理在资源层。
- 工具叫 `bash`，但 `subprocess.run(shell=True)` 用的是 `/bin/sh`。macOS 自带的 `/bin/sh` 是 POSIX 模式的 bash 3.2，`<(...)` 这类写法会报语法错误（上面那次 5 轮就碰上了）；别的系统上 `/bin/sh` 指向什么不一样，结果也可能不同。工具集在 EP56 讲。

## 试一试

模型：阿里云百炼 `deepseek-v4.1-flash`。每次跑之前先清空 `./workspace`。同一个任务每次跑，模型走的步数和写法都可能不一样，下面写的是存进 `examples/` 的那一次。

**1. 写、跑、回答**（循环完整走一遍）

```bash
uv run --env-file .env onion-agent --yes "在 workspace 里写一个 fizzbuzz.py，打印 1 到 15 的结果，然后运行它确认输出正确"
```

应该看到：3 轮，消息数 1 → 3 → 5；第 1 轮写文件，第 2 轮运行（退出码 0），第 3 轮回答。自己核对 `python3 workspace/fizzbuzz.py` 的第 3、5、15 行。完整输出：[ep54-fizzbuzz.txt](../examples/ep54-fizzbuzz.txt)

**2. 工具出错**（`call_tool()` 把异常变成文字交回去）

```bash
mkdir -p workspace && printf '{\n  "port": 8080\n}\n' > workspace/config.example.json
uv run --env-file .env onion-agent "用 read_file 读 config.json，告诉我里面 port 的值；这个文件不存在的话，就读 config.example.json。"
```

应该看到：第 1 轮结果是红色的「工具执行出错：FileNotFoundError …」，循环没崩；第 2 轮改读 `config.example.json`；最后回答 8080。完整输出：[ep54-tool-error.txt](../examples/ep54-tool-error.txt)

**3. 拒绝执行**（不加 `--yes`，提示时按 `n`）

```bash
uv run --env-file .env onion-agent "用 bash 看一下工作目录里有哪些文件。"
```

应该看到：`执行这条命令吗？[y/N]` 按 `n` 后，结果是红色的「用户拒绝执行这条命令。」；第 2 轮模型不再要工具，反过来问你想换什么办法。完整输出：[ep54-refuse.txt](../examples/ep54-refuse.txt)
